# AgentRAG

Данные:
Спаршенные скриптом статьи с arxiv. 

Корпус: 14 статей с arXiv по теме RAG/retrieval, скачаны через `download_papers`,
собраны в `structured_corpus.jsonl` через `build_corpus` (1 032 828 символов).
Вопросы: 40 штук (30 отвечаемых + 10 без ответа), у каждого есть `evidence`.

**Нарезка.** Две версии:
- по строкам (`chunk_lines`) — 3825 кусков, метаданные: doc_id, title, section, url
- по 400 символам (`chunk_chars`) — 2568 кусков, без section

**Эмбеддинги.** `text-embedding-3-small`, 512 измерений, дисковый кэш по sha1(текста).

**Поиск.**
- `search_numpy` — перебор на нормализованных векторах (косинус = скалярное произведение)
- Milvus (AUTOINDEX, COSINE) — коллекция `lines`, фильтр по `title` работает
- recall@k для k=1,3,5,10,20 на обеих нарезках — см. `img/recall.png`

| k | по строкам | по 400 символов |
|---|---|---|
| 1 | 0.18 | 0.18 |
| 5 | 0.28 | 0.32 |
| 10 | 0.35 | 0.42 |

**Гибрид (BM25-like + RRF).** Слова отдельно ощутимо сильнее вектора на recall@1
(0.30 против 0.18), RRF-слияние пока даёт результат хуже, чем один keyword-поиск
(0.25–0.28 против 0.30) — веса не подобраны, см. вопрос ниже.

**rag_answer / plain_answer / отчёт.** Пять конфигураций (без RAG cheap/strong,
RAG k=5 cheap/mid/strong) — точность 2.5–20%, `img/money_rag.png`.
k-sweep на cheap-модели: k=1→10% до k=10→25%, recall с ростом k ещё не вышел на
плато на исследованном диапазоне.

**Разбор провалов.** На RAG k=5 почти все ошибки — «не нашли», «нашли, но ответили неверно» — единичные случаи. Значит узкое
место — ретривер, а не генератор.

**Отказы.** 10/10 вопросов без ответа честно отклонены (`NOT_FOUND`), медиана
близости лучшего куска у отвечаемых и неотвечаемых вопросов разная — можно
резать по порогу до вызова модели.
